# 合成数据实验：画像能提供哪些异常信号

本实验使用固定种子 `20261121`，构造对照集和观测集。两份数据均为 2,400 行、15 个字段，覆盖 30 天。所有记录均为合成数据；数据中没有异常标签，注入说明单独保存在 `manifest.json`，不传给画像函数。

观测集包含缺失、重复、金额尾部放大、负值和零值、状态编码变体、空字符串、无效日期、时间先后变化及局部字段归零。另保留两个正常对照：币种一直是 CNY，门店运费一直为零。

实验分别运行基础库的基础画像、扩展画像和分组或派生列画像，再用 AVA 自身的默认画像及只读 SQL 独立复核。画像本身没有自动读取注入清单、配置业务阈值或生成业务结论。

| 观测对象 | 实际画像结果 | 能说明什么 |
| --- | --- | --- |
| 整体规模与重复 | 两组行数都是 2,400；订单号不同值数从 2,400 降至 2,360；观测集有 40 个完整重复组 | 总行数正常，不能说明数据没有漏失或重复 |
| 客户字段缺失 | 缺失率从 0 升至 4%；全表缺失单元格比例只有 0.322% | 整体比例会稀释单个字段的问题，是否允许缺失仍由用途决定 |
| 金额尾部 | 最大值从 549.30 增至 39,484；均值从 180.11 增至 262.54，上升 45.8%；中位数从 150.83 降至 146.43，仅下降 2.9% | 少量尾部变化显著影响均值，大部分记录的中心位置变化较小 |
| 分位点 | P95 从 434.006 变为 438.977；P99 从 528.0535 变为 540.65；P99.9 从 549.0101 变为 27,656.223 | 只看常用分位点可能看不到极少量尾部变化，需要结合最大值和更高分位点 |
| 负值与零值 | 金额出现 8 个负值、40 个零值，对照集均为 0 | 是数值特征，不能仅凭此判断为错误、退款或优惠 |
| 状态编码 | 不同值数从 3 增至 6；新增 `"PAID"`、`"paid "`、`" paid"`，各 8 条 | 需要查看完整频数才能识别具体的大小写和空白变体；基础不同值数只能提示词表变化 |
| 联系方式 | NULL 为 20 条，空串与纯空格各 20 条；最短长度从 23 降为 0 | NULL 统计不包含空串和空白；是否将三者合并为缺失，需要调用方明确口径 |
| 日期内容 | `settlement_date` 两组的 NULL 都为 0；显式指定 date 角色后，观测集发现 16 条不可解析日期 | 非空不代表可解析，日期语义需要调用方明确提供 |
| 两个数值字段的关系 | 金额与结算金额的 Pearson 相关系数从 1 降到约 0.1156 | 字段关系发生变化，可以据此进一步查看分布或样本，不能据此确定原因 |
| 局部运费归零 | 全局运费零值率只从 25% 升到 26.875%；最近 7 天的 partner × South 切片，35 条记录的零值率从 0 升为 100%，不同值从 5 个降至 1 个 | 分组能放大整体统计中不明显的变化；切片本身不等同于业务异常结论 |
| 渠道与日期覆盖 | 按日 × 渠道补齐组合后，平均记录数仍为 20，但出现 2 个零计数组；11 月 13、14 日的 partner 均为 0，另有组合增至 30 | 均值和总量也可能被等量重复抵消；缺失组合需要在合适的粒度下观察 |
| 时间差 | 对 `ingest_time - event_time` 派生列做画像，出现 25 个负值，最小值为 -3,600 秒 | 两个字段各自可解析、范围正常，不代表它们的先后关系正常；原因仍需上下文 |

对照组同样重要。币种不同值数在两组中都为 1；门店运费零值率在两组中都为 100%。因此，“常量列”“零值率高”等观察可以是正常特征，不能直接当作错误。报告中的“质量观察”仍是统计事实，没有把这些特征自动标记成业务故障。

这次实验说明，现有基础库已能提供一些有用的侧面信号。更细的信号往往来自 AVA 选择的观察粒度、字段角色和派生列，未必需要增加业务诊断规则。实验没有测量通用异常检测的准确率、误报率或漏报率。

运行以下命令可以重新生成数据、画像和带断言的复核结果：

```sh
npm run build
PROFILING_PYTHON=.venv/bin/python node examples/anomalies.mjs
```

Python 环境沿用 `python-requirements.txt`；本实验的日期解析阶段使用 Python。默认输出到 `artifacts/anomaly-experiment/`，也可以将输出目录作为第一个参数传入。脚本断言两份 schema 一致，并检查重复、缺失、日期解析、分布、分组和派生列的关键结果；新实验不修改画像内核。

运行后生成的主要文件包括：

- `clean.parquet`、`observed.parquet`：保留类型、NULL 和空字符串区别的主数据。
- `clean.json`、`observed.json`、对应 CSV：便于查看或测试其他读取方式。
- `manifest.json`：合成范围、随机种子、注入数量和正常对照。
- `basic.json`：七个基础指标的原始结果。
- `profiles.json`：整体、分组、派生列及列对的完整结构化画像。
- `signals.json`：从画像结果提取的对照值，不包含推测的业务原因。
- `verification.sql`、`verification.json`：独立 SQL 复核及原始结果。
- `ava-verification.sql`：用于 AVA 单文件会话的复核 SQL，默认模型名为 `data`，执行前应通过 `ava schema` 确认。
- `report.html`：使用现有渲染器生成的中文离线画像报告，包含十个整体或切片对象。

本次还实际通过 AVA 加载 `observed.parquet`，核验了默认画像，并执行整体复核、日渠道覆盖、近期渠道地区分组、时间差和状态标准化五条只读查询。返回行数分别为 1、120、16、1、1，均未截断；结果与基础库一致。相关 `ava-*.sql` 和 `ava-*.json` 保留在本次生成目录中，脚本重跑本身不会自动重跑 AVA CLI。

AVA 的复核流程如下；会话和数据源仍由 AVA 管理：

```sh
ava source artifacts/anomaly-experiment/observed.parquet > /tmp/anomaly-session.json
ANOMALY_DATASET_ID=$(node -p 'JSON.parse(require("fs").readFileSync("/tmp/anomaly-session.json", "utf8")).datasetId')
ava schema "$ANOMALY_DATASET_ID"
ava profile "$ANOMALY_DATASET_ID"
ava query "$ANOMALY_DATASET_ID" --dsl @artifacts/anomaly-experiment/ava-verification.sql
ava dispose "$ANOMALY_DATASET_ID"
```

CSV 读取也经过实际验证：当前 AVA 默认读取器把 20 个空字符串读成了 NULL，使 `contact` 的 NULL 数从 20 变为 40，非 NULL 的空白值从 40 变为 20，行数仍为 2,400。这属于读取口径变化。本实验以 Parquet 为准，不混用 CSV 和 Parquet 的缺失统计，也不将这种差异误判为画像计算错误。
